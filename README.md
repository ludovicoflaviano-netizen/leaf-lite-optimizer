# Leaf Lite Optimizer

A small companion plugin and configuration kit for Leaf/Paper 1.21.11. It provides a lightweight `/leaflite` runtime report and documented, reversible tuning steps. It does not patch Minecraft internals or silently alter gameplay.

## Important memory limit

**512 MB is not a realistic, reliable allocation for a 50-player Java server.** The JVM, server, plugins, loaded chunks, entities, networking and world data all need memory. This project cannot guarantee 50 players on 512 MB, zero lag spikes, or unchanged gameplay under that limit. Treat 512 MB as suitable for testing, not a production target. For 50 players, start with a host allocation measured in multiple GiB and benchmark your actual world and plugin set.

## What is included

- A minimal Java plugin that reports heap use, online players, loaded chunks and entity counts.
- A conservative `server.properties` example.
- A safe optimization checklist for world pre-generation, mob/AI load, redstone behavior, Java flags and profiling.
- No entity AI replacement, no global mob suppression, no forced garbage collection, and no custom redstone engine.

## Build

Requires JDK 21 and Gradle 8.10+ (or a compatible recent Gradle release).

```sh
gradle build
```

Copy `build/libs/leaf-lite-optimizer-1.0.0.jar` to the server's `plugins/` folder, then restart. Run `/leaflite` or `/leaflite status` in-game or from console. This is a diagnostics plugin, not a magic performance patch.

## Vanilla redstone

Leaf configuration keys can change between builds. Back up your Leaf config, inspect the config generated by your exact Leaf build, and choose its documented **vanilla redstone implementation** option if available. Do not paste keys from a different version. Test clocks, observers, pistons, quasi-connectivity-dependent contraptions and farms after changing it. Vanilla redstone compatibility can cost performance compared with alternate implementations.

## World pre-generation

Use a maintained chunk pregenerator compatible with your exact server version, such as Chunky. Set a reasonable world border first, pregenerate the intended playable area during low traffic, and watch disk space. Pregeneration moves chunk-generation work out of normal play; it does not reduce the memory required by chunks players keep loaded.

## Baseline tuning

1. Start from the defaults shipped by your exact Leaf build. Back up configs before changing anything.
2. Set a sensible `view-distance` and `simulation-distance` (example below). Lower values change how far players can see and where entities/ticks are processed.
3. Remove unused plugins and audit expensive repeating tasks. Profile before blaming mobs or redstone.
4. Keep gameplay-affecting mob caps, despawn rules, AI and tick settings at defaults if preserving vanilla behavior matters.
5. Use a current supported Java 21 runtime and a conservative collector configuration. Do not copy random JVM flag bundles or set `-Xmx` above the host's real memory limit.
6. Run a timed test with representative players, farms, redstone and exploration. Capture timings/spark reports and compare before/after.
